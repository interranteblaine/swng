# M5 — The Round on the Phone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the v1 round experience in `apps/web` — a crew creates, joins by code, scores every game format with two taps (offline included), watches standings live, and finalizes to an archived card — gated by a two-browser Playwright field test playing a full 18 of fourball + skins against the deployed beta stack.

**Architecture:** `docs/architecture.md` §3 — the web app is a subscriber to `createRoundSession` (the ONLY scoring API), plus four plain HTTP commands (create/join/add-game/finalize) spoken directly from `@swng/contracts` schemas. The phone folds the same `@swng/domain` the server folds; the UI renders `RoundState` + `GameState[]`, never invents math.

**Tech stack:** React 19 + Vite + Tailwind 4 (per `docs/implementation-plan.md` header), react-router 7, `useSyncExternalStore` over the session's `onChange`, Vitest + Testing Library (happy-dom) for components, Playwright for the field-test gate.

## Global Constraints

- Work directly on `main`; `pnpm validate` green at every commit. Validate stays hermetic: `apps/web` joins `pnpm -r` lint/typecheck/build/test; the Playwright field test lives behind an explicit root script `pnpm e2e:field` (needs beta + installed browsers), like `e2e:beta`.
- Every commit message ends with: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
- TDD; comment the why only; conventions per `docs/engineering-conventions.md`.
- **Layer law extended to the app (lint-enforced in this plan):** `apps/web` imports `@swng/client`, `@swng/contracts`, `@swng/domain` ONLY — never `@swng/application`, `@swng/adapters-*`, `@swng/lambda`.
- **Two taps is a hard product constraint** (`product.md` §9): posting any score — for anyone, including picked-up/conceded — is exactly 2 interactions from the idle round view (tap cell → tap value). The field test asserts it structurally.
- **Design decisions fixed by this plan** (do not relitigate):
  - **Per-tab identity.** `deviceId` is minted per browser tab (`crypto.randomUUID()` cached in `sessionStorage["swng:deviceId"]`), and the IndexedDB outbox database name incorporates it (`swng-outbox-<deviceId>`), so concurrent tabs never share an opCounter OR a PersistedSync record (both halves of the M4→M5 handoff collision). Same-tab reload keeps its deviceId and therefore recovers its own queue. Known accepted caveat (why-comment it): browser tab-duplication copies sessionStorage — a duplicated tab shares the queue until its next mint; ledgered for M9 hardening, not solved here.
  - **Round credentials in `localStorage`** keyed `swng:round:<roundId>` holding `{ token, golferId, name, joinCode }` — refresh and revisit re-enter the round without re-joining; a second tab reuses the same credential (same golfer) with its own deviceId/outbox, which is exactly the supported multi-scorer case.
  - **`state()`/`games()` keep throwing before hydration**; the new `hydrated()` accessor is the UI's guard. No `undefined`-returning variants (no `| null` state unions — conventions).
  - **Digest trigger:** a between-holes digest appears when a hole first becomes *complete* (every participant has a cell for it) and is dismissed by tap or by the next score entry. Its content is derived purely from `games()` before/after — no game-specific logic outside the per-kind renderers.
  - **No service worker / PWA install** (explicitly out of scope per master plan); offline-first means the session SDK keeps working through dead zones in an already-open tab.
  - **Fixture courses ship in the bundle** (M6 replaces with real course search): the picker offers `fixtureLinks` (9 holes) and the new `fixtureLinks18`, both exported from `@swng/domain`.
  - **Styling bar:** sunlight-readable and glove-friendly means big touch targets (score pad buttons ≥ 56px), high contrast, the card rendered as a real scorecard grid (dots as literal dots). No design-system buildout, no component library dependency — Tailwind utilities only.
  - **The gate oracle is the domain.** Task 2's 18-hole deck numbers below are hand-verified in this plan (fourball 2&1; skins Ann 0 / Bo 7 / Cal 0 / Dee 8, carried-out 3); the domain deck test pins them against the engines, and the Playwright field test then asserts the SAME numbers through the full UI→SDK→server→SDK→UI pipeline.

```ts
export interface RoundSession {
  // ... everything from M4 unchanged, plus:
  hydrated(): boolean;   // true once a round-created event is held (first pull/socket batch
                         // ingested it); state()/games() THROW until then — hydrated() is
                         // the render guard. Never regresses to false.
}
// games(): GameState[] is now IDENTITY-STABLE between changes: same array reference
// until the underlying state changes (cached beside cachedState) — required for
// useSyncExternalStore, which treats a fresh reference as "store changed" and loops.
// close(): now awaits any in-flight sync pass before the final persist — a sync pass
// always settles promptly (offline is a resolved outcome, not a hang), so close()
// resolving means no more store writes or notifies will occur.
// ingest(): now short-circuits (no invalidate, no persist, no notify) when a batch
// confirmed nothing new, pruned nothing, and left the cursor unchanged — a socket echo
// of an already-pulled batch is silent. This SUPERSEDES M4's keep-once-per-batch
// decision (final-review triage deferred the change to M5, where UI renders make the
// cost real). Update the M4 test that pinned notify-per-batch for pure duplicates.
```
