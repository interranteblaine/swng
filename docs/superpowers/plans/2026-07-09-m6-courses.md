# M6 — Courses Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** real courses replace bundled fixtures — a golfer enters their home course from its paper scorecard once (fast), the crew verifies it, round setup searches and picks it, and every dot/allowance/differential computes from it — gated by an add-a-course-and-play-on-it e2e whose dot expectations are hand-verified in this plan.

**Architecture:** `docs/architecture.md` — Course is a boring CRUD entity (NO event sourcing) in the existing `core` DynamoDB table, with **versioned immutable tee sets** (corrections create a new version; provenance + verification are per-version metadata). Rounds keep freezing a `CourseCard` snapshot at start — the existing `startRound` contract does not change; the web app simply sources the card from the course API instead of a bundled fixture. Layer flow: `domain/course` (pure) → `application` use cases behind a `CourseStore` port → `adapters-dynamodb` → `lambda` routes → `apps/web`.

**Tech stack:** unchanged (Zod contracts, deps-applied use cases, declarative route table, DynamoDB single-table items in `core`, React web).

- **Design decisions fixed by this plan** (do not relitigate):
  - **`CourseCard` (the frozen-snapshot shape) is untouched.** `courseCardOf(course)` must return a value assignable to the existing `CourseCard` consumed by `startRound` — compile-level compatibility is the invariant; a round started from a stored course is indistinguishable from one started from a fixture.
  - **Course APIs are `auth: "none"` in M6** — identity is M7; abuse controls are M9 (add "course API rate limiting / auth" to the M9 hardening list). `enteredBy`/`verifierName` are display-name strings, why-commented as beta-grade until M7 ties them to identity.
  - **One search normalization function, exported from domain, used on BOTH write and query sides** (`courseNameKey`: lowercase, trim, collapse internal whitespace). Invariant: a course always matches a prefix of its own entered name. Search is prefix-only in v1 (a crew enters its two home courses; fuzzy is not earning rent yet).
  - **Tee-set versioning:** posting a tee set whose name matches an existing one creates a NEW version and supersedes the old (one endpoint covers add and revise — correction is the common case, why-comment it). Versions are immutable; verifications attach to a version and do NOT carry over on revision (a corrected card is unverified until someone re-verifies it — that's the point of verification).
  - **The `core`-table course item is one document per course** (pk `COURSE#<id>`, sk `COURSE`), guarded by a `revision` attribute + conditional write. Invariant: two concurrent writers cannot silently lose a tee set — the loser's conditional write fails and the use case retries on a fresh read (bounded, jittered, like the journal's pattern).
  - **The web create flow drops bundled fixtures entirely** — search is the only picker. The M5 field test keeps working by ensuring "Fixture Links 18" exists as a REAL course record through the public API (search-first, create-if-absent in the spec's setup) — the fixture data itself stays exported from `@swng/domain` for tests.
  - **Join screen gets a real tee picker** via a new read-only peek (`GET /rounds/peek?code=`) that returns course name + tee summaries only — no `roundId`, no card, no participants (the join code is the capability; peek widens it by nothing that matters, and `joinRound` remains the only way in). This closes the M5 "join tee is free text" adjudication.
  - **This milestone touches the backend, so the ledgered backend carries activate** (Task 4): finalize must validate settle-ability BEFORE appending `round-finalized` (today a finalize on an unresolvable round wedges permanently — confirmed by two reviewers); the M4-accepted finalize head-seq race gets its conditional append; `consoleLogger`'s `data.level` sibling clobber gets fixed.
  - **Gate oracle:** the synthetic-but-realistic 18-hole card in Task 6 (SI permutation and dot expectations hand-verified below). The literal "paper scorecard in under 10 minutes" half of the master gate is a HUMAN check — the automated gate proves the flow is keyboard-first/single-screen and the dots are right; the user is invited to time their real home course against the dev server at close.

**Interfaces (produced — exact names later tasks consume):**

```ts
// course/course.ts — pure functions over immutable data, DomainError on violation
export type Provenance = "community" | "imported";
export interface TeeSetVersion {
  readonly version: number;              // 1-based, monotonic per tee name
  readonly status: "current" | "superseded";
  readonly provenance: Provenance;
  readonly enteredBy: string;            // display name; identity lands M7
  readonly enteredAtMs: number;
  readonly verifications: readonly { readonly name: string; readonly atMs: number }[];
  readonly tee: TeeSet;                  // the existing scoring shape, embedded whole
}
export interface Course {
  readonly courseId: CourseId;
  readonly name: string;
  readonly teeSets: readonly TeeSetVersion[];  // all versions, all names
}
export const createCourse: (input: { courseId: CourseId; name: string; tee: TeeSet; enteredBy: string; nowMs: number; provenance?: Provenance }) => Course;
export const addTeeSet: (course: Course, input: { tee: TeeSet; enteredBy: string; nowMs: number; provenance?: Provenance }) => Course;
  // INVARIANT: same tee name ⇒ new version (prior current → superseded, verifications NOT carried);
  // new name ⇒ version 1. Returned course always has exactly one current version per tee name.
export const verifyTeeSet: (course: Course, input: { teeName: string; verifierName: string; nowMs: number }) => Course;
  // attaches to the CURRENT version; duplicate verifier name on same version is a no-op (idempotent)
export const courseCardOf: (course: Course) => CourseCard;
  // current versions only, in first-entered tee-name order — MUST remain assignable to the
  // CourseCard startRound freezes (compile-level: the return type IS CourseCard)
export const courseNameKey: (name: string) => string;  // lowercase, trim, collapse whitespace — the ONE
  // normalization used by both the store's GSI write and search's query (invariant above)
```

Tee-set validation (a `validateTeeSet` internal both create/add call; each violation is a `DomainError` with a stable code): holes length 9 or 18; `number` runs 1..N in order; `strokeIndex` a permutation of 1..N; par ∈ 3..6; yardage an integer ∈ 1..800; rating ∈ 30..90; slope an integer ∈ 55..155 (USGA bounds); tee `name` non-empty, ≤ 40 chars, and unique per course case-insensitively among current tee names (for a NEW name — a matching name is a revision, not a violation). Course `name` non-empty ≤ 80 chars.

